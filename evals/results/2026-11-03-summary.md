## 结论

1. **hybrid 在 dev 上提升明显，但没有在 test 上复现。** dev 上 Recall@5 从 0.9375 提升到 1.0、MRR 从 0.757 到 0.932；test 上 Recall@5 两者都是 0.7692，MRR/nDCG 反而略降。说明 dev 的提升有一部分来自这 32 题的具体分布，不能当作线上收益。
2. **hybrid 的延迟成本是确定的。** 检索 p95 从 19 ms 涨到 348 ms（+约 330 ms），首 token/总 p95 也相应变慢。对交互式问答来说，这个成本没有换到 test 上的召回提升，因此 **不把 hybrid 设为默认**；保留 `RETRIEVAL_MODE=dense`，hybrid 通过请求参数 `retrieval_mode="hybrid"` 或环境变量按需开启。
3. **引用准确率低是 extractive 的产物，不是检索失败。** extractive 会把上下文里所有片段都标成引用，所以引用召回率高（0.73–0.98）、准确率低（0.33–0.43）。真实 LLM 只会引用实际使用的片段；这一项要在接入 LLM 后重测。
4. **负样本拒答为 0，是阈值校准的真实结论。** 见下一节：余弦分数无法把“技术相邻但语料没有答案”的负样本与正样本分开。

## 阈值校准（dev 集）

dev 上负样本的 `best_dense_score`：

```text
q-neg-001  0.6270
q-neg-002  0.6199
q-neg-005  0.6113
```

正样本最低的几道：

```text
q-g2-006  0.5840
q-g1-002  0.5889
q-g1-008  0.6053
q-g2-004  0.6229
q-g1-023  0.6259
```

- 要让阈值拒掉任意一个负样本，至少要大于 0.6113；
- 此时会同时误拒 3 道正样本（0.5840 / 0.5889 / 0.6053），误拒率 9.4% > 5% 目标；
- 要拒掉全部 3 个负样本（阈值 > 0.6270），误拒 5 道正样本（15.6%）。

**结论：没有阈值能在误拒率 ≤5% 的前提下拒掉负样本。** 因此 `score_threshold` 保持 `null`（等价于不启用），拒答准确率如实记为 0。
下一步应改用 **LLM 拒答提示**（让模型判断“资料是否足以回答”）或 **cross-encoder 相关性门控**，而不是继续调余弦阈值。

## 失败样例

1. **q-g2-020（dense/hybrid 都未命中）**：问 `status` 模块里 403 对应的常量；gold 是
   `zh/reference/status/`（语料里确有 4 个 chunk），但两路都优先召回
   `tutorial/response-status-code/`、`advanced/response-change-status-code/`。
   原因：API reference 页与 tutorial 页语义高度重叠，符号级问题没有把 reference 页排上来。
2. **q-g2-021**：问普通 `def` 路径函数里如何返回 `UploadFile` 底层文件对象；gold 是
   `zh/reference/uploadfile/`，检索优先命中 `tutorial/request-files/`。
   同样是 reference vs tutorial 的排序问题。
3. **q-g2-022**：问 `Depends()` 的 `use_cache` 默认值；gold 是
   `zh/reference/dependencies/`，检索命中 `advanced/advanced-dependencies/`、
   `tutorial/query-param-models/`。hybrid 的关键词一路也没把 reference 页拉上来。
4. **q-neg-003（Kafka）未被拒答**：`best_dense_score=0.519`，但阈值未启用（见上节）；
   extractive 仍从 top-5 片段拼了一段答案。
5. **q-neg-004（gRPC/proto）未被拒答**：`best_dense_score=0.633`，与正样本分数完全重叠；
   这类“技术相邻但语料没有答案”的负样本，余弦分数本身就不具备判别力。

## 未做 / 诚实边界

| 项 | 状态 | 原因 |
|---|---|---|
| 重排（rerank） | 未做 | 本地没有 reranker 模型；不引入无法评测的 provider |
| 查询改写（rewrite） | 未做 | 没有可用 LLM；且会增加首 token 延迟 |
| 语义缓存 | 未做 | 精确缓存已有；语义缓存缺少审计样本，容易答非所问 |
| 答案正确率 / 忠实度 | 未评 | 生成侧用 extractive，只评引用/拒答/延迟 |
| nDCG@10 | 实际为 nDCG@5 | top_k=5，前 10 位里只有 5 条参与 |
| 语料规模 | 141 篇 / 855 chunk | 只抓 FastAPI 中文站；未扩到其他站点 |
| test 规模 | 13 道可回答 | 50 题 70/30 切分的结果；结论需谨慎外推 |

## 复现命令

```text
# 起服务（确保 rag-api 在 8001）
docker compose up -d --build --no-deps api rag-api embedder

# 从宿主机跑（需要 httpx + pyyaml）
python -m scripts.eval_rag --config dense  --base-url http://localhost:8001 --split test --runs 2 --out evals/results/2026-11-03-dense-test
python -m scripts.eval_rag --config hybrid --base-url http://localhost:8001 --split test --runs 2 --out evals/results/2026-11-03-hybrid-test

# 或用 eval 容器（结果经 ./evals 挂载回仓库）
docker compose --profile eval run --rm eval python -m scripts.eval_rag --config dense --split test
```
